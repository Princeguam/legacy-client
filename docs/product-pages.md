# Cooperative workspaces

Member pages: Home, Transactions, Contributions, Portfolio, Profile, Settings, and Feedback. The admin workspace adds Members and a fuller home page with cooperative totals, spending, membership counts, pending items, and annual progress. Both use the same design tokens and locally owned components. Financial examples come from one illustrative ledger in `src/lib/product-data.ts`; portfolio allocations, confirmed totals, annual targets, and member progress reconcile. Pending transactions are excluded from confirmed balances. Missing returns and profile data remain unavailable instead of becoming zero or invented account details.

## Reviewing pages

Visit `/preview`, linked from sign-in, to choose `/preview/user/home` or `/preview/admin/home`. Public previews use explicit sample identities and never create an auth session. Their context cannot grant access to protected routes. Preview labels remain visible throughout navigation. Profile edits are drafts for the current screen only. Feedback drafts stay on the current screen and are never sent. Notifications show a numeric unread count and illustrative updates, and support marking them as read for the current workspace view. Settings apply appearance/device preferences locally; notification delivery and cooperative planning submissions are not connected.

Protected pages live under `/user` and `/admin`. Root and successful sign-in take a valid existing session to its role’s home. `ProtectedRoute` checks validity, expiry, and exact `user`/`Admin` role. Cross-role navigation returns to the signed-in role’s home. Future backend endpoints must enforce server authorization independently. No backend functionality was added for these pages; the prior login service is unchanged.

Profile identity comes from the actual login session outside previews. Other account fields remain “Not provided” until a backend integration is explicitly authorized. Illustrative financial figures remain labelled even inside authenticated workspaces.

## Interactions and responsive behavior

Transactions support search, type/status and inclusive date filters, detail dialogs, ten-record pagination, and sample CSV export. Members support search, status filters, sorting, eight-record pagination, and links to full member-details pages at `/admin/members/:memberId` (or `/preview/admin/members/:memberId`). Member pages show membership information, confirmed/pending contributions, annual progress, known investment allocations, and a searchable, paginated history scoped to that member. Unknown members have a clear unavailable state; missing investment data remains unavailable. Fund details show sample allocated capital and unavailable returns/valuation fields. Charts offer three-month, six-month, and year-to-date views with equivalent data tables.

The sticky top bar is 64px tall, with theme and sample-notification controls. Standard fields, buttons, and icon targets are 44px tall. Active sidebar links use a single semantic accent fill. Settings and Feedback sit at the bottom of the sidebar. Collapse hides the wordmark and leaves only the original tree and navigation icons; dark-mode branding uses the original tree as a pale inverse mask on a transparent background, without a backing block. These density refinements follow the user’s explicit instructions while retaining the approved palette and typography.

The shell uses collapsible 240px desktop navigation (256px from 1600px). Below 960px, a borderless hamburger in the sticky top bar opens a native modal drawer from the left; no bottom navigation is rendered or reserved. The drawer includes the brand, every role-appropriate destination, and Settings/Feedback at the bottom. The native dialog supplies focus trapping and dismissal; Escape, the close button, backdrop clicks, and selecting a destination close it. Background scrolling is locked while open, and switching to a desktop viewport closes the drawer. Transactions and members become labelled records on narrow screens; chart data remains in a contained scroll region. Full amounts, dates, and statuses are retained. Theme changes synchronize between the app bar and Settings. Reduced-motion and forced-colours styles are supplied.

`npm run build`, `npm run lint`, `npm run test:pages`, and `npm run test:auth` verify compilation, ledger consistency, role guards, route rendering, and filters. DOM interaction checks additionally covered navigation focus, the mobile menu, chart periods and data, search/pagination/date validation/export, member navigation/history, notifications, feedback drafts, profile drafts, sidebar collapse, and synchronized theme/device preferences. Native dialog methods were mocked for those checks; they do not prove browser focus trapping or responsive rendering. Browser/keyboard/zoom/mobile/forced-colours rendering still needs a browser-capable environment when Chrome startup is blocked. The transaction interaction checks also cover exact amount/date validation, accepted receipt preservation after errors, review cancellation, repeated-save prevention, draft retention during navigation, unchanged financial totals, receipt URL cleanup, and clearing drafts when the workspace changes.

## Transaction drafts and motion

Members can open `transactions/new` from Home or Transactions. A labelled native form records type, date, exact NGN amount, description, optional payment reference and notes. One optional PDF/JPEG/PNG receipt up to 10 MB can be attached, previewed, opened, or removed. Validation preserves form values and the accepted file. A review dialog precedes **Save transaction draft**; matching type/date/amount/reference (or description when no reference is supplied) prevents duplicate local entries.

Drafts and their File objects are memory-only, scoped to account and workspace. They survive page navigation within the workspace and clear on reload, sign out, or workspace change. The separate draft list supports review and confirmed removal; object URLs are revoked when previews close. Drafts do not enter the illustrative ledger, CSV exports, graphs, or balances. No transaction or receipt endpoint is connected.

Selected statistic cards use the original tree silhouette as a subtle watermark. Page entries, exact amounts, graph lines, dialogs, and navigation controls use approved motion tokens, without invented intermediate financial values. Lazy page loading retains the workspace shell and shows the original tree fading from faint to brand teal (inverse white in dark mode), with no artificial loading delay. Reduced-motion disables transitions and chart drawing and keeps the static logo/status; forced colours uses a system-colour loading silhouette and hides decorative watermarks.
