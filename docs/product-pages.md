# Workspace pages and data boundaries

Member and admin workspaces share the approved responsive shell and actual-session role guards. Public `/preview` routes are layout previews with empty records and no account API requests. Seeded application accounts, ledgers, feedback and notifications have been removed; original design references and explicitly illustrative design-system component examples remain.

Home and Portfolio show the existing construction page within the shell until their integrations are supplied/authorized. Transactions consumes member/admin server-paginated history and fresh details. Admins can create confirmed payments and approve/reject pending payments after review and acknowledgement. The transaction summary cards and annual target remain labelled zero placeholders until summary endpoints exist. See `docs/transactions.md` for contracts, exact BigInt kobo handling and current backend findings.

Member Add transaction uploads its required receipt and submits a pending payment after review/acknowledgement. Both roles select an active bank through `/api/bank/no`; administrators select a user through `/api/admin/user/no`, with no raw ID fields. Inputs/files survive errors and acknowledged uploads are reused after failed writes. Previews use empty options and never fetch/upload/submit; existing memory drafts remain isolated from API history and summaries.

Profiles consume actual own-profile GET/PUT. The editor exposes ten personal/contact fields, with four required and six optional without Optional hint text. Existing passports appear in the profile and top bar through the shared AccountAvatar; missing/broken images fall back to initials. Membership omits the account identifier. Saves preserve inputs on errors and update stored account data only after validated acknowledgement while preserving tokens. See `docs/profile.md`.

Notifications consume real unread counts and list/read actions after acknowledgement; preview inboxes are empty. Feedback submission remains acknowledged-only, and the admin inbox/details preserve server pagination/category/date order; preview records are empty. See the focused integration documents.

Admin Bank accounts consumes the paginated list and reviewed creation endpoints. Account numbers preserve leading zeros, saves require matching acknowledgement and failed refresh retains labelled results. Update writes remain unconnected. See `docs/bank-accounts.md` for routes and backend findings.

Settings connects own-password changes for both roles and provides sign-out alongside its device-local theme/notification preferences and screen-only cooperative planning form. Passwords remain in memory, clear only after acknowledgement and retain their values on errors. Sign-out is also available in the top bar and is removed from the footer. See `docs/settings.md`. Preferences do not imply email/push delivery or persisted cooperative changes.

Keep the sticky 64px top bar, 44px targets, desktop sidebar/rail and borderless left drawer below 960px. Native dialogs retain inert background, Tab/Shift+Tab wrapping, busy Escape protection and focus return. Preserve the original tree and semantic tokens. Run build, lint, all regression scripts and focused browser checks; mocked checks do not establish live connectivity or full accessibility.

Admin Members and Member details consume the user directory/profile and scoped transaction endpoints. Add user now connects creation and avatar upload; own profiles edit the expanded contacts and passport. Workspace lists use scrollable native tables on mobile without wrapping text or pinning the first column. Profile/Add user dialogs share centered avatar circles and a wider responsive desktop width. API messages use reusable Sonner toasts with unchanged backend errors. See `admin-users.md` and `uploads.md`.
