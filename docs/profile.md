# Own profile

Members and administrators share `GET /api/profile` and `PUT /api/profile` through `userService.ts`. The stored bearer token accompanies every request. `apiClient.ts` validates the response envelope and preserves backend messages/codes/status; `apiUser.ts` selects public fields and normalizes exact roles. ID/role must match the signed-in account and a deleted account cannot update its session.

The editor now includes first/middle/last names, email, phone, date of birth, address/state/LGA/gender, occupation, next-of-kin name/relationship/phone and emergency-contact name/relationship/phone. First/last names, email and phone remain required. Other fields remain optional without Optional labels; DOB is nullable in the current Prisma schema. Calendar validation rejects invalid/future birth dates. `profileRequest.ts` trims and selects permitted fields and validates saved values against acknowledgement.

Avatar editing uses the centered circle to open the native image chooser. Accepted JPEG/PNG selection immediately uploads through `utilService.ts`. Save changes waits for upload acknowledgement and sends its URL as `passport` without another upload. Failed uploads retain the accepted file and offer Retry upload; replacing/removing the file cancels its pending request. Both the profile and top bar change only after a matching profile response. The shared dialog is 720px on desktop with existing mobile bounds/body scrolling. Failed requests keep inputs/accepted images; a failed PUT reuses an already uploaded avatar on retry. See `uploads.md`.

The page fetches fresh account information on entry, displays passport/initials, role icons, personal/contact fields and membership dates. Membership omits the account identifier and does not infer activity because `isActive` is not selected. API errors use Sonner with unchanged backend messages, alongside retry controls for failed reads. Saves show a toast only after acknowledgement. Field errors stay beside their controls. Stored user data refreshes without replacing tokens/expiry; late/aborted/other-account responses cannot overwrite the session. Previews use empty sample accounts and make no requests.

The current backend retains most optional values when their supplied values are falsy. Blank optional values are therefore omitted; this form does not claim to clear them or delete an existing avatar. The owner added occupation/contact writes during this batch. No server file was edited by the frontend agent.

`test:profile` and `test:uploads` verify request/response contracts and ownership. The focused mocked upload browser suite checks all text fields, avatar selection, preserved errors, duplicate/pending guards, retry reuse, top-bar/session refresh, centered/wider responsive dialogs, toasts and preview isolation. Live API/storage behavior, actual browser zoom and screen readers require separate verification.
